## Quick start

<Callout type="info">
The adapter auto-detects `TWITCH_CLIENT_ID`, `TWITCH_CLIENT_SECRET`, `TWITCH_WEBHOOK_SECRET`, and `TWITCH_BOT_USERNAME` from the environment.
</Callout>

```typescript title="lib/bot.ts" lineNumbers
import { Chat } from "chat";
import { createTwitchAdapter } from "@chat-adapter/twitch";
import { createMemoryState } from "@chat-adapter/state-memory";

export const bot = new Chat({
  userName: "mybot",
  adapters: {
    twitch: createTwitchAdapter(),
  },
  state: createMemoryState(),
});

bot.onNewMention(async (thread, message) => {
  await thread.reply(message, `Hi @${message.author.userName}!`);
});
```

The memory state adapter keeps subscriptions and locks in process memory, which suits local development. Use [Redis](/adapters/official/redis) or [PostgreSQL](/adapters/official/postgres) in production.

```typescript title="app/api/webhooks/twitch/route.ts" lineNumbers
import { after } from "next/server";
import { bot } from "@/lib/bot";

export async function POST(request: Request) {
  return bot.webhooks.twitch(request, {
    waitUntil: (task) => after(() => task),
  });
}
```

## Platform setup

The adapter runs as a Twitch [cloud chatbot](https://dev.twitch.tv/docs/chat/authenticating/): a dedicated Twitch account for the bot, an app access token for the API calls, and one-time authorizations from the bot account and each broadcaster.

### 1. Register a Twitch application

1. Create a Twitch account for the bot, then open the [Twitch developer console](https://dev.twitch.tv/console/apps) and register an application. Set **OAuth Redirect URLs** to `http://localhost:3000`, the address the Twitch CLI listens on during the authorization in step 2. The adapter doesn't use a redirect at runtime. Choose **Confidential** as the client type so Twitch issues a client secret.
2. Copy the **Client ID** to `TWITCH_CLIENT_ID`, generate a **Client Secret**, and copy it to `TWITCH_CLIENT_SECRET`.
3. Set `TWITCH_BOT_USERNAME` to the bot account's login name.
4. Generate a random string of 10 to 100 characters for `TWITCH_WEBHOOK_SECRET`, for example with `openssl rand -hex 32`.

### 2. Authorize the bot account

Sign in as the bot account and authorize your application with these scopes:

| Scope | Why |
| --- | --- |
| `user:read:chat` | Receive `channel.chat.message` events as the bot |
| `user:write:chat` | Send chat messages as the bot |
| `user:bot` | Let the app act as the bot with an app access token |
| `moderator:manage:chat_messages` | Optional. Delete chat messages in channels where the bot is a moderator |
| `user:manage:whispers` | Optional. Send and receive whispers |

The [Twitch CLI](https://dev.twitch.tv/docs/cli/token-command/) can run this flow for you:

```bash
twitch token --user-token --scopes "user:read:chat user:write:chat user:bot user:manage:whispers"
```

Chat only needs the authorization to exist; the adapter mints app access tokens itself. Keep the printed refresh token if you want whispers (see [Whispers](#whispers)).

### 3. Get permission from each broadcaster

For every channel the bot joins, either have the broadcaster authorize your application with the `channel:bot` scope, or make the bot account a moderator of the channel (`/mod <bot login>` in chat).

### 4. Subscribe to chat events

Deploy your webhook route first. Twitch sends a verification challenge as soon as you subscribe, and the adapter answers it. The callback URL must use HTTPS on port 443.

```typescript title="scripts/subscribe.ts"
import { bot } from "@/lib/bot";

await bot.initialize();
const twitch = bot.getAdapter("twitch");
const callbackUrl = "https://your-domain.com/api/webhooks/twitch";

// Repeat for every broadcaster user ID the bot should listen to.
await twitch.subscribeToChat("141981764", callbackUrl);
// Optional: receive whispers sent to the bot.
await twitch.subscribeToWhispers(callbackUrl);
```

Subscriptions persist on Twitch's side until they are deleted or revoked, so run this once per channel rather than on every deploy. Creating a subscription that already exists fails with a `ValidationError`.

## Webhooks

Twitch delivers [EventSub webhook](https://dev.twitch.tv/docs/eventsub/handling-webhook-events/) requests as POSTs. The adapter:

- Verifies `Twitch-Eventsub-Message-Signature`, an HMAC-SHA256 of the message ID, timestamp, and raw body, with a timing-safe comparison, and returns 403 when it doesn't match.
- Rejects messages whose timestamp is more than 10 minutes old, as Twitch recommends, to block replays.
- Answers `webhook_callback_verification` challenges with the raw challenge string.
- Logs `revocation` messages with the subscription type and reason, such as `authorization_revoked`.
- Routes `channel.chat.message` and `user.whisper.message` notifications, and acknowledges other subscription types without processing them.

Twitch can deliver a notification more than once. Chat SDK deduplicates by message ID, so a retry doesn't run your handler twice. Respond quickly by passing `waitUntil`: Twitch revokes subscriptions that time out too often.

## Mentions and replies

A message counts as a mention when it contains an `@mention` fragment for the bot, or when it replies to one of the bot's messages. Messages the bot sent itself are ignored.

`thread.post()` sends a regular chat message. `thread.reply(message, ...)` sets `reply_parent_message_id`, so Twitch shows your message as a reply to the viewer's.

When a viewer replies to a message, `message.replyTo` holds the message they replied to, with its text and author. Twitch has no history API, so this is the only context you get for a reply. Pass both messages to `toAiMessages` so an agent can see what the viewer is responding to:

```typescript
const prompt = await toAiMessages(
  message.replyTo ? [message.replyTo, message] : [message]
);
```

Chat SDK treats a chat room as one thread. After `thread.subscribe()`, `onSubscribedMessage` receives every message in that channel's chat, so filter in your handler on busy channels.

## Message formatting

Twitch chat is plain text on a single line. The adapter renders markdown as plain text, joins the parts of a card with ` · `, collapses line breaks into spaces, and converts emoji placeholders to Unicode. Messages longer than 500 characters are cut at the last word that fits and end with `…`. Twitch turns emote names it recognizes, such as `Kappa`, into emotes. File uploads aren't supported.

When Twitch accepts a request but the message fails one of its checks, Send Chat Message reports `is_sent: false`. The adapter then throws a `ValidationError` that includes Twitch's `drop_reason`.

## Whispers

Whispers are Twitch's direct messages. Inbound whispers arrive in `onDirectMessage` once you call `subscribeToWhispers`. To start a whisper, open the thread through the adapter, because Chat SDK can't infer the platform from a numeric Twitch user ID:

```typescript
const twitch = bot.getAdapter("twitch");
await bot.thread(await twitch.openDM("4145994")).post("Thanks for the raid!");
```

Sending a whisper needs a user access token for the bot account with `user:manage:whispers`. Set `TWITCH_REFRESH_TOKEN` so the adapter refreshes that token and persists the rotated refresh token in the state adapter, or set `TWITCH_USER_ACCESS_TOKEN` (or pass an async `userAccessToken` provider) to supply tokens yourself.

Twitch requires a verified phone number on the bot account and limits whispers to 40 unique recipients per day, 3 per second, and 100 per minute. A whisper can be up to 500 characters if the recipient hasn't whispered the bot before, and up to 10,000 otherwise.

## Deleting messages

`deleteMessage` removes a chat message with Delete Chat Messages. The bot account must be a moderator of the channel (or the broadcaster) and must have authorized `moderator:manage:chat_messages`. Twitch only deletes messages from the last 6 hours, and never the broadcaster's or another moderator's messages. Whispers can't be deleted.

## Streaming

Twitch chat messages can't be edited, so the adapter buffers the stream and posts once when it completes.

## Message history

Twitch has no chat history API. `fetchMessages` and `fetchMessage` return the messages this adapter instance received or sent, up to 200 per thread, and the adapter enables `persistThreadHistory` so Chat SDK keeps longer history in the state adapter.

## Thread IDs

```
twitch:{broadcasterUserId}       # a broadcaster's chat room
twitch:whisper:{userId}          # a whisper conversation with one user
```

Examples: `twitch:141981764`, `twitch:whisper:4145994`.

A chat room thread ID is also its channel ID, so `bot.channel("twitch:141981764").post(...)` posts to that chat room.

## Limitations

- Twitch has no reactions, typing indicators, message edits, or interactive components.
- In a shared chat session, messages from the other channels arrive with `source_broadcaster_user_id` set on `message.raw.event`. Messages the adapter sends go only to the chat room in the thread ID, which is Twitch's default for app access tokens.
- Twitch rate-limits chat messages. The adapter raises a `429` response as `AdapterRateLimitError`.
- Look up users with `bot.getAdapter("twitch").getUser(id)`. `bot.getUser(id)` can't infer the platform from a numeric Twitch user ID.
